A self-correcting loop for PhaseCast projections

Sacrifice fidelity now; buy a durable process that rapidly corrects as its projections are tested. Three of four agents finished before the run was cut short — this is what converged, what rules, and what is still missing.

Verdict (interim, director-anchored). The loop is buildable this week. All three finishing agents independently arrived at the same skeleton — append-only JSONL prediction register → named tester per projection class → scripted scoring → dated corrections, never silent model edits — and the same top poison family: anything that lets a wrong projection score as right. The director's binding addition, which no worker surfaced: PhaseCast was trained on MAGEMin-simulated labels, so PhaseCast-vs-MAGEMin agreement is teacher-agreement (distillation fidelity), not accuracy about rocks. That agreement is cheap, will score high, and will dominate the register unless labelled. The single most dangerous poison risk is reading it as validation.

1. The design

ENTRY (OOD gate) → PROJECTION (register entry) → TEST (named tester) → SCORE (script) → UPDATE (calibration.json)
  • Entry condition: ≥7 of 9 majors, unrenormalized; provenance tag (analogue: / synthetic: / park:); declared class (protolith-igneous-equivalent vs metamorphic-equilibrium); OOD gate verdict trusted / borderline / untrusted (envelope: SiO₂ ≤ 80, MgO ≤ 18, sum ≥ 90, plus immobile-basaltic ratios). untrusted still runs — stamped hypothetical-only.
  • Register: append-only register/predictions.jsonl; every entry carries input hash, PhaseCast commit SHA, MAGEMin db version, provenance. Resolutions never edit claims.
  • Update: calibration.json recomputed from the register, never hand-edited. Corrections are dated rubric or input-rule changes, never silent model changes. No retraining inside the loop.

4. Safe vs poison sacrifices

The test: after the sacrifice, does a wrong projection still score as wrong? Noise is survivable; a sacrifice that makes wrong look right is fatal.

SacrificeRulingWhy
Regional analogues for park rocksSAFEif provenance-stamped and never cited as park support
Volcanic-only heads on amphibolitesSAFEif registered as igneous-equivalent
Single P–T point instead of a pathSAFEcoarser, but the scored quantity is phase presence at one stated condition
Missing traces left blankSAFEcorrect "not measured" encoding
Coarse 7-group mappingSAFElossy but symmetric — affects projection and score equally
Zero-filling or imputing blanksPOISONcreates a fake measurement that can be scored
Renormalizing to 100%POISONbiases posterior and MAGEMin comparison in the same direction — corrupts the score
1970s USGS semi-quant as park inputPOISONlacks majors — any filled version is invented
Calling teacher-agreement "validation"POISONthe director's top poison risk — see verdict
Scoring garnet/epidote/scheelitePOISONoutside the scored groups or the vocabulary entirely
"Consistent with" as a verdictPOISONmakes almost any observation pass
Post-hoc rank/threshold choicePOISONchoosing what counts as correct after seeing results
Thinning the register to raise the hit ratePOISONselection bias — every attempted projection gets a line
Pooling synthetic with real analoguesPOISONsynthetic inputs inherit their parent's answer and inflate agreement

Solo-loop guards: cap open predictions at 10 (hit cap → next session is scoring-only); frozen rubric file, dated amendments only; SHA + input-hash health check opens every session; 20-minute minimum week; skipped weeks logged, not hidden; corrections require a threshold count of scored predictions in the same class.

Minimum viable first month: ≥10 projections registered, ≥6 scored (rest NOT SCOREABLE with reason, not open), ≥2 classes covered, ≥1 dated correction applied, ≥2 poisons logged as rejected, 4 README status lines, no open prediction >14 days old.
